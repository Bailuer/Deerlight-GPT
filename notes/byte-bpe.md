# Byte-level BPE learning module

Implementation: `byte_bpe.py`. Tests: `test_byte_bpe.py`.

Run from the project directory:

```powershell
python byte_bpe.py
python -m unittest test_byte_bpe -v
```

Read in this order:

1. `count_pairs`: count adjacent pairs; overlaps count.
2. `merge_pair`: replace one chosen pair left to right; matches cannot overlap.
3. `_reset`: initialize 256 byte tokens and an empty rule dictionary.
4. `train`: count, choose, merge, repeat. This is not gradient-based training.
5. `encode`: use fixed rules in learned rank order, not new frequencies.
6. `decode`: concatenate expanded bytes, then decode UTF-8 once.
7. `save` / `load`: preserve exact IDs, ordered rules and Special Tokens.

IDs 0-255 are bytes; 256/257/258 are BOS/EOS/PAD. Merges start at 259.
The requested vocabulary size is a maximum; tiny corpora may exhaust pairs.
Literal text such as `<BOS>` is encoded as text, not as a Special Token.

This transparent version has no regex pre-tokenization and can merge across
spaces within a document. Passing a list of documents prevents cross-document
merges. Its repeated scans are not intended for large-scale production training.

For a real corpus, split raw text into training and validation text FIRST.
Train the Tokenizer only on training text, then encode both with the same rules.
Measure compression as UTF-8 byte count divided by token count (exclude added
Special Tokens). An empty string has no defined compression ratio.

The existing GPT entry points and character-level checkpoints are unchanged.
Model integration must bind a saved Tokenizer to a newly trained Model and use
its actual vocabulary size. Merely swapping in a same-size Tokenizer is unsafe.
Compare different Tokenizers on identical held-out text with byte-normalized
metrics, not raw mean per-token Cross-Entropy alone.

Valid text round-trips exactly. Arbitrary generated byte sequences can be invalid
UTF-8: `decode` is strict by default; use `errors="replace"` for display if needed.
